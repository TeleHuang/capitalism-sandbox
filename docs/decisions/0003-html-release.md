# ADR 0003 — HTML 发行版技术路线（已确认）

- 状态：已确认（人选 A）
- 日期：2026-10-24
- 背景：人已明确：Python 版用于验证逻辑，最终发行版只包含一个 HTML 文件，电脑双击或手机浏览器打开即可游玩。
  当前仓库只有 Python 参考实现和命令行入口，`web/` 尚未实现。

## 目标

- 用户不需要安装 Python，打开 HTML 即可运行/交互；
- 经济逻辑与 Python 参考实现一致；
- 可离线、可静态托管（GitHub Pages 等）；
- 后续能接 LLM API 和更完整的界面。

## 选项

### A. JavaScript/TypeScript 重写引擎 + 静态 HTML（推荐）

- 前端和模拟引擎都在浏览器运行；
- Python 只负责生成黄金运行样例和参数校准；
- 优点：启动快、可离线、部署简单；
- 缺点：两套实现，必须用固定随机种子的 JSON 样例做交叉验证。

### B. Pyodide：在浏览器里运行 Python

- 通过 WebAssembly 加载 Python 引擎；
- 优点：只有一套逻辑，天然一致；
- 缺点：首次加载体积大（约 10MB+）、运行较慢，移动端体验较差。

### C. Python 后端 + HTML 前端

- 优点：逻辑唯一，前端轻；
- 缺点：需要服务器，不是“纯 HTML 发行版”，部署和成本更高。

### D. Python 离线生成 HTML 快照

- 优点：实现简单；
- 缺点：用户只能看回放，不能交互运行，不满足“模拟器”的产品预期。

## 已确认路线

采用 **A**：

1. Python 参考实现继续作为唯一权威逻辑；
2. 增加 `web/`：TypeScript/JavaScript 引擎 + 图表，构建时内联为单个 HTML；
3. Python 导出固定随机种子的黄金运行 JSON；
4. JavaScript 引擎在 CI 中复现这些黄金样例，误差超过阈值即失败；
5. 不再采用 B（Pyodide）：它需要外部 WASM/Python 运行时，不符合“单个 HTML 文件、离线打开”的硬要求。

## 已确认事项

- 采用 A：JavaScript/TypeScript 引擎 + 单文件 HTML；
- Python 继续作为逻辑参考实现和黄金样例生成器；
- 发行版必须完全离线，不依赖服务器、外部资源或 Python 运行时；
- 单文件意味着构建时要把 JS、CSS、必要的配置和默认场景全部内联到一个 `.html` 文件中。
